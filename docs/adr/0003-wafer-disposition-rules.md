# ADR-0003 · 웨이퍼 처분은 규칙 엔진이 결정한다

- 상태: 채택
- 관련 코드: `stacklens/advisor/report.py::decide`, `DecisionRules`

## 규칙 (순서대로 적용)
1. 예측 패턴이 **Near-full** 이거나 웨이퍼 불량률 **≥ 50%** → `SCRAP_CANDIDATE` (적층 투입 부적합 후보)
2. 고위험 다이 비중 **≥ 20%** → `HOLD_REVIEW` (웨이퍼 보류, 엔지니어 검토)
3. 임계값 이상 고위험 통과 다이가 1개 이상 → `SCREEN_HIGH_RISK` (그 다이만 제외하고 투입)
4. 그 외 → `RELEASE`

고위험 임계값은 REAL-proxy 16단·잠재불량 1% 실험의 최적 선별 비율(통과 다이 위험 상위 약 1.4%)에서 나온다.

## 근거와 한계
- 50%·20%는 **현업 기준이 아니라 이 프로젝트의 가정값**이다. 공개된 기준을 찾지 못했다.
  Near-full 웨이퍼는 불량이 전면에 퍼져 있어 살아남은 다이의 잠재 위험을 추정할 이웃 정보가 없다는 점이 1번의 근거다.
- 값은 `DecisionRules` 한 곳에만 있고, LLM 프롬프트 v3·v4는 같은 값을 사실 ID(`[R1]`~`[R3]`)로 받는다. 두 곳이 어긋날 수 없다.

## 왜 LLM이 결정하지 않나
측정 결과(`artifacts/results/summary.json`의 `advisor.table`, 12웨이퍼 × 3회):
- 규칙을 주지 않은 v1: 규칙 엔진과의 일치율이 모델별 58%·61%·100%, 반복 간 조치 일치 58~100%
- 규칙을 준 v2~v4에서도 gpt-4.1-mini 67~97%, gpt-5.4-mini 83~92%
- gpt-5.5만 모든 버전에서 100%였지만, 같은 모델도 실행에 따라 흔들릴 수 있다(이전 측정에서 v1 97%)

결정은 재현 가능해야 하므로 코드가 하고, LLM의 다른 제안은 덮어쓰지 않고 "사람 검토"로 표시한다.
